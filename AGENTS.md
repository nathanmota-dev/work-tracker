# Work Tracker

Work Tracker is an Electron desktop app for managing the job-search process. It helps users discover job opportunities on LinkedIn, save and track roles, organize applications, and keep related job-search activity such as recruiter outreach, interviews, and profile metrics in one place. LinkedIn and browser automation are provided through configurable MCP integrations, while compatible coding agents can be connected through ACP.

## Technology stack

- Desktop shell: Electron, built with electron-vite.
- Backend and CLI: TypeScript on Node.js 24+, with an HTTP and WebSocket API.
- Persistence: SQLite through Node.js's built-in `node:sqlite` module.
- Integrations: Model Context Protocol SDK (`@modelcontextprotocol/sdk`), WebSocket support (`ws`), configurable LinkedIn and Chrome MCP servers, and ACP agent processes.
- Frontend: Vite, React, Tailwind CSS, shadcn/ui components, and TanStack Router.
- Tests: Vitest is used for both backend and frontend tests. Backend tests run in Node; frontend tests use jsdom and Testing Library.

## Mandatory verification before completing a task

Whenever a task creates, modifies, or deletes application code, tests, runtime assets, dependencies, scripts, or build/runtime configuration, run **every command below**, in order, from the repository root before reporting the task as complete. This applies to backend/server, CLI, Electron main/preload, and frontend changes, regardless of how small the change is or which layer it affects. A targeted test or a partial checklist does not replace the full verification.

```bash
npm run typecheck
npm test
npm run test:backend:integration
npm run package
node scripts/smoke-electron.mjs
node scripts/smoke-electron.mjs node_modules/.bin/electron-vite dev --watch --noSandbox
node scripts/smoke-electron.mjs './release/Work Tracker-1.0.0.AppImage' --no-sandbox
node scripts/smoke-apply.mjs node_modules/.bin/electron-vite dev --watch --noSandbox
node scripts/smoke-apply.mjs './release/Work Tracker-1.0.0.AppImage' --no-sandbox
npm run test:e2e
npm run lint
npm run test:infra
npm run audit:ci
npm run test:backend:coverage
npm run test:frontend:coverage
npm run quality:check
npm run benchmark
npm run performance:check
```

Use Node.js 24 or newer, installed npm dependencies, and a graphical environment for the Electron smoke checks. If the app version or artifact name changes, use the AppImage generated by the current `npm run package` in the last command.

- `npm run typecheck` checks backend/desktop and frontend types.
- `npm test` runs backend unit tests and frontend tests; it does **not** run backend integration tests, so `npm run test:backend:integration` is mandatory separately.
- `npm run package` already runs the production build, including type checking and CLI compilation. Separate `npm run build` and `npm run build:cli` calls are not additional required checks.
- All three Electron smoke commands are mandatory: built app, development mode, and packaged AppImage.
- The two Apply smoke checks compile a generic LaTeX fixture and verify that both PDF viewers render with the bundled worker in development and the AppImage. They require `latexmk`, `pdflatex`, Poppler (`pdfinfo` and `pdftotext`), and the example template’s LaTeX packages (including Roboto, titlesec, enumitem and fancyhdr); they use an isolated workspace and a fake ACP process.
- `npm run test:e2e` rebuilds production output and runs the Playwright Electron suite, including all 14 sidebar routes and functional journeys with isolated SQLite workspaces and synthetic ACP/MCP integrations. It requires a graphical environment (or Xvfb), `latexmk`, `pdflatex`, `pdfinfo`, and `pdftotext`. See `docs/e2e.md` for coverage, fixtures, debugging and CI.
- `npm run lint` runs ESLint for both layers and must report zero errors and warnings. `npm run test:infra` tests the gate scripts and workflow triggers/path filters. `npm run audit:ci` blocks critical npm advisories and warns about high ones; it needs registry access.
- `npm run test:backend:coverage` and `npm run test:frontend:coverage` run each unit suite once with coverage and stamp the reports; `npm run quality:check` then enforces the 80% per-layer coverage floor, no regression against `scripts/quality-baseline.json`, duplication, and the 350-line file and 100-line function limits.
- `npm run benchmark` runs the backend and frontend microbenchmarks; `npm run performance:check` compares them with `scripts/benchmark-baseline.json`, or captures a bootstrap reference when none exists. See `docs/ci.md` for CI behavior. Add newly introduced checks to this checklist.
- Watch commands are development tools, not completion checks.

Fix verification failures and rerun the affected checks before completing the task. In the final response, summarize the checks executed and their results. If an environment problem prevents a required check from running or passing, explicitly name the blocked check and the reason; never silently skip it or claim that verification passed.

### Final step: update the installed app from main

For tasks that require the checklist above, updating the locally installed app is the final required step **only when every required check has passed and the verified source is in the worktree checked out on `main`**. A failed, blocked, or skipped required check prevents the update. If the source changes after verification, verify those changes before updating.

Tasks on other branches or worktrees must not update the installed app, even if their checks pass. After merging into `main`, run the full checklist in the `main` worktree before updating; do not reuse another branch's build or verification results.

Ensure Work Tracker is closed, then run the following block from the root of the verified `main` worktree. Rebuild production output here because the development smoke check can overwrite `out/`. The unpacked build updates the existing installation without generating another AppImage or recreating the menu entry.

```bash
(
  set -eu
  if [ "$(git branch --show-current)" != "main" ]; then
    printf '%s\n' 'Update the installed app only from the main worktree.' >&2
    exit 1
  fi

  install_dir="$HOME/.local/opt/work-tracker"
  if [ ! -x "$install_dir/work-tracker-app" ]; then
    printf '%s\n' 'Work Tracker is not installed; follow the installation instructions in README.md.' >&2
    exit 1
  fi

  npm run build
  ./node_modules/.bin/electron-builder --linux --dir --config desktop/electron-builder.yml
  rsync -a --delete release/linux-unpacked/ "$install_dir/"
  cp web/src/public/logo.png "$install_dir/icon.png"
)
```

Keep application data in `~/.work-tracker` untouched. Report the installation update result in the final response; if the update cannot finish, report the reason instead of claiming the installed app is current. See [README.md](README.md#instalação-no-linux-pelo-menu-de-aplicativos) for the initial installation and menu registration.

### Exceptions

The checklist and installation update may be skipped only when the task makes **no file changes** (for example, planning/Plan mode, read-only investigation, or answering a question) or changes **only documentation or prose-only text files** (for example, `README.md`, `AGENTS.md`, or documentation under `docs/`). The installation update also does not apply to tasks on other branches or worktrees, as specified above; their full verification checklist remains mandatory for implementation changes.

The exception depends on the actual changes, not the task label or file format: source code, CSS, HTML, scripts, and configuration files are text files but are **not** documentation-only changes. If a task mixes documentation with any implementation change, the full checklist remains mandatory.
